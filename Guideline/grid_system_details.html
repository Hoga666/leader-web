栅格系统

以内容区可用宽度为判断基准，用列、沟槽与边距建立跨 Leader 家电屏的一致布局秩序。栅格只约束内容显示区，不约束导航与按键区。

1. 核心规则

内容显示区采用 12 列栅格，沟槽 16dp，支持 2、3、4、6 等分。12 列是内容区的统一标尺，不代表每块屏幕都显示 12 列；内容区变窄时，系统降为 8 列或 4 列，保持信息顺序与跨列比例。

大屏12 列
中屏8 列
小屏4 列

同一组件可用 12 列跨度记录设计意图，再映射到各档位可用列数。例如半宽区域可表达为 6/12、4/8、2/4。

2. 栅格构成

栅格由容器、边距、列和沟槽共同组成。沟槽与边距均为 8 的倍数，沟槽固定 16dp。

3. 从硬件分辨率到设计尺寸

分辨率只决定像素数量，不能直接决定栅格。先得到 CSS 逻辑宽度，再扣除固定区域，按内容区可用宽度选档位。下方换算器输入后，会自动匹配对应的栅格布局图。

01

确认物理像素

从屏幕规格书读取横向物理像素，如 480、1280、1920。

02

确定 DPR

Linux 按 1 处理（物理分辨率视为 CSS 逻辑像素）；Android 按设备实际 DPR 取值。

03

计算 CSS 逻辑宽度

CSS 逻辑宽度 = 物理宽度 ÷ DPR。

04

扣除固定区域

内容区可用宽度 = CSS 逻辑宽度 − 导航区 − 按键区 − 间距。

05

依内容区可用宽度选档

跨过断点时重排与折叠，不进行整体等比缩放。

4. 响应式断点

断点基于内容区可用宽度，不使用整屏宽度。优先使用容器查询（@container）；只有页面根布局才使用视口媒体查询。

5. 跨档位的组件行为

01

重排

从 12 列降到 4 列时，8+4 主次布局改为两个 4 列区块，主任务在前；不要把两栏同比缩窄。

02

跨列

同一组件跨档位保持相对比例，建议映射 2/4 → 4/8 → 6/12。正文容器在大屏不超过 8 列，控制单行长度，避免阅读疲劳。

03

文字对齐

栅格约束容器的左右边缘。容器内文字只需起始边对齐容器内容边界，结束边由自然换行决定，不强制对齐列边缘。

04

固定与流动

列宽与中、小屏容器随内容区可用宽度流动；沟槽 16dp 在所有档位保持固定。大屏容器达到上限后不再拉宽，只在内容区两侧增加留白。

05

方向变化

设备方向、分屏状态或系统栏出现变化后，重新测量内容区可用宽度。保持信息优先级和阅读顺序，不保证元素物理位置不变。

6. 设计与验收清单

设计检查

✓ 设计稿标注物理分辨率、DPR、固定区域宽度与内容区可用宽度

✓ 内容块左右边缘对齐列边缘，无内容落在沟槽内

✓ 相邻内容块之间空隙等于沟槽 16dp

✓ 文字起始边对齐容器内容边界，结束边自然换行

✓ 大屏容器达到上限后不再拉宽，且居中

开发验收

✓ 容器居中基准为内容区可用宽度，未使用 100vw 或脱离文档流

✓ 小屏下无横向滚动，内容自动堆叠

✓ 未出现 5 等分或 7 等分分栏

✓ 导航区在小屏下已切换形态，内容区未被挤压

✓ 开始/暂停按键区在小屏下已改变位置，未遮挡内容

例外： 图表、视频和沉浸式背景可跨越列与沟槽，但其标题、图例、操作入口和数据标注仍应对齐栅格。
